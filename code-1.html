The ladder — what survives which scramble

A ruled scene — leaves at every integer, an arrow, the metric — put under five rungs of scrambling: rotate, translate, scale, shear/affine, projective. Every table value is recomputed from the scrambled geometry on every press — nothing is remembered except the baseline. The purple-highlighted row is always the weakest scramble used so far; rotation can't raise it back. Watch what dies where: length dies at scale, the leaf grid dies at affine, the count and the cross-ratio die only at projective.

Press a scramble button (or keys 1–5, R to reset) · every number below is recomputed live from the scrambled image · the highlighted row = weakest scramble used

The survival table

RungWhat it isKillsKeeps
rotatea rigid motion about Onothingeverything — lengths, angles, the leaf grid, midpoint, stack, origin, crossings, cross-ratio
translatea shiftthe origin claim (O moves)lengths, angles, the leaf grid, midpoint, stack, crossings, cross-ratio
scalea uniform dilationabsolute length (and angles' measure)ratios: midpoint, stack proportion, leaf spacing, crossings, cross-ratio
shear / affineany invertible linear map + shiftangles, equal leaf spacing (the residual lights up)parallelism, midpoints, the stack proportion, crossings, cross-ratio
projectiveany invertible 3×3 up to scalemidpoints, parallelism, even spacings — the whole affine inheritanceincidence, straightness, and the two crown jewels: the count and the cross-ratio

Read the table as one statement. Each rung keeps exactly the ratios its group preserves: rigid motions keep everything, translations give up only the anchored origin, dilations keep ratios but not sizes, affines keep parallelism and midpoints, and the projective rung keeps incidence alone — yet even there the leaf count along a segment and the cross-ratio of four collinear points refuse to move. That refusal is the whole point: the last surviving numbers are the projective invariants, and they are measured here from the true scrambled image, never from a remembered answer.

Every table value is recomputed from the current image on every render (F1 fix): the pierce count samples f(ap(p)) along the segment in image space, the crossing rings sit at the images of the true intersections (F2 fix), the stack H is renormalized after every compose so w stays bounded (F3 fix), and the cross-ratio check uses a relative tolerance against accumulated float drift.
